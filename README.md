# CSS 라이브러리 동향

## CSS 라이브러리 트렌드 변화

**1. 전통적 CSS와 한계**

- HTML, CSS, JS를 분리하는 전통적 방식은 전역 스코프 문제와 스타일 충돌, 유지보수 어려움 등의 한계가 드러남

**2. CSS 전처리기의 등장: Sass**

- Sass(및 SCSS)는 변수, 중첩(Nesting), 믹스인(Mixin) 등 객체지향적 개념을 도입해 CSS의 재사용성과 유지보수성을 크게 높임
- 반복되는 스타일을 변수와 함수처럼 관리하고, 선택자 중첩을 통해 구조화된 스타일링이 가능해짐
- 여러 파일에서 변수와 믹스인을 import하여 대규모 프로젝트에서도 일관성 있게 스타일을 관리할 수 있게 됌

**3. 컴포넌트 기반 프레임워크의 부상과 CSS Modules**

- React, Vue 등 컴포넌트 기반 개발이 대세가 되면서, CSS도 컴포넌트 단위로 관리할 필요성이 커짐
- CSS Modules는 각 컴포넌트별로 고유한 className을 생성해, 스타일의 범위를 컴포넌트로 한정시켜 전역 충돌 문제를 해결함

**4. CSS-in-JS의 등장: styled-components 등**

- CSS-in-JS는 CSS를 JS 코드 내부에서 직접 작성하고, 컴포넌트 단위로 스타일을 관리하는 방식
- 대표적으로 styled-components, Emotion, Styled JSX 등이 있음
- 장점:
  - 스타일이 컴포넌트와 함께 관리되어 모듈성과 재사용성이 높아짐
  - JS 변수, 함수와의 통합으로 동적 스타일링과 테마 적용이 쉬움
  - 자동으로 고유 className을 생성해 스타일 충돌 방지
- 단점:
  - 컴포넌트 렌더링 시마다 스타일이 동적으로 생성되어, 렌더링이 빈번한 앱에서는 성능 이슈가 있을 수 있음
  - 정적으로 관리되는 전통적인 CSS방식과 달리 런타임에 js파일이 실행되면서 style을 생성, **런타임 오버헤드** 발생
    - 규모가 커지고 렌더링이 빈번할수록 성능이 저하될 수 있음

**5. 최근 동향: Atomic CSS, Utility-First, TailwindCSS**

- CSS-in-JS와 함께 Atomic CSS(유틸리티 클래스 기반, ex. TailwindCSS)도 대세로 부상
- 스타일을 미리 정의된 작은 단위(클래스)로 쪼개 조합하는 방식으로, 빠른 개발과 일관성, 퍼포먼스 최적화가 가능해짐

## zero-runtime 스타일링 솔루션 : Vanilla Extract, Panda CSS

### **1. Vanilla Extract**

https://github.com/vanilla-extract-css/vanilla-extract

- **정의**: Vanilla Extract는 TypeScript 기반의 CSS 프리프로세서로, 스타일을 TypeScript 코드로 작성하면 빌드 타임에 정적 CSS 파일로 변환해줍니다. 런타임 오버헤드가 전혀 없는 zero-runtime 스타일링 솔루션
- **주요 특징**
  - **타입 안전성**: 스타일을 TypeScript로 작성해 타입 검증과 자동완성 등 기존 TS 도구 생태계를 그대로 활용할 수 있음
  - **로컬 스코프**: 생성되는 클래스명은 파일 단위로 스코프가 지정되어 전역 충돌이 없음
  - **정적 CSS 생성**: 빌드 시점에 CSS 파일이 생성되어, 런타임에 JS가 스타일을 주입하지 않습니다. 이는 styled-components, Emotion 등 기존 CSS-in-JS의 성능 한계를 극복
  - **테마/변수 지원**: createTheme, CSS 변수 등으로 테마 관리와 동적 스타일링이 가능
  - **프레임워크 독립**: React, Vue 등 프레임워크에 구애받지 않고 사용할 수 있음
- **변화 의미**: 기존 Sass, CSS Modules, CSS-in-JS의 장점(모듈화, 동적 스타일, 타입 지원 등)은 살리면서, 런타임 성능 문제와 번들 크기 이슈를 해결한 최신 트렌드의 대표 주자

---

### **2. Panda CSS**

https://github.com/chakra-ui/panda

- **정의**: Panda CSS는 Chakra UI 팀이 만든 zero-runtime CSS-in-JS 라이브러리로, 소스 코드에서 스타일 정보를 추출해 빌드 타임에 정적 CSS 파일을 생성
- **주요 특징**
  - **정적 컴파일**: AST 파싱을 통해 소스에서 스타일 정보를 추출, 빌드 시점에 CSS 파일을 생성하여 런타임 오버헤드가 없음
  - **유틸리티/Atomic CSS 지원**: Tailwind처럼 유틸리티 클래스 기반의 스타일링도 지원하며, Atomic CSS 방식으로 불필요한 CSS가 줄어듦
  - **타입 안전성과 자동완성**: TypeScript와의 통합으로 타입 검증 및 자동완성이 뛰어남
  - **디자인 토큰/Variants**: 디자인 토큰, 컴포넌트 variants(레시피) 등 디자인 시스템 구축에 최적화
  - **조건부 스타일링**: 상태(hover, focus 등)나 반응형 스타일을 손쉽게 적용가능
  - **SSR 및 서버 컴포넌트 지원**: Next.js 등 서버 컴포넌트 환경에서도 문제없이 사용할 수 있음
- **변화 의미**: 기존 styled-components, Emotion 등 런타임 CSS-in-JS의 단점을 극복하면서, Tailwind의 퍼포먼스 장점과 CSS-in-JS의 개발 생산성을 결합한 최신 솔루션

### **3. 변화 과정에서의 위치**

| 라이브러리/방식                  | 주요 장점                                  | 주요 단점/한계                  | 최근 트렌드와의 차별점             |
| -------------------------------- | ------------------------------------------ | ------------------------------- | ---------------------------------- |
| Sass/SCSS                        | 변수, 믹스인, 구조화, 재사용성             | 전역 스코프, 동적 스타일 한계   | 타입 지원, 정적 생성 미흡          |
| CSS Modules                      | 컴포넌트 단위 스코프, 충돌 방지            | 동적 스타일 한계, 타입 미지원   | 정적 생성, 타입 지원 미흡          |
| CSS-in-JS (styled-components 등) | 동적 스타일, 컴포넌트 단위, JS 통합        | 런타임 오버헤드, 번들 크기 증가 | 런타임 성능 문제                   |
| **Vanilla Extract**              | 타입 안전, 정적 CSS, 테마, 프레임워크 독립 | 설정 복잡, 일부 기능 미지원     | zero-runtime, 타입 안전, 정적 생성 |
| **Panda CSS**                    | 정적 생성, 유틸리티/Atomic, 타입 안전      | 설정 필요, 생태계 초기 단계     | zero-runtime, Atomic, 디자인 토큰  |

---

### **요약**

- **Vanilla Extract**와 **Panda CSS**는 모두 런타임 오버헤드 없는 정적 CSS 생성, 타입 안전성, 컴포넌트 단위 관리, 디자인 시스템 친화성 등 최신 프론트엔드 스타일링 트렌드를 대표함
- 기존 Sass, CSS Modules, CSS-in-JS의 장점을 계승하면서, 퍼포먼스와 DX(개발 경험)를 모두 강화한 차세대 CSS 라이브러리로 주목받고 있음
